# BABA TTS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a strictly local Node/Hono and React/Zustand application that acts as an OBS-embeddable YouTube Live Chat dashboard with moderation capabilities.

**Architecture:** A monolithic-style local application where a Hono backend on port 7060 handles SQLite storage, Google OAuth, YouTube API polling, and WebSocket broadcasting. The React SPA connects to the WebSocket to display and moderate chat.

**Tech Stack:** Node.js, Hono, SQLite (better-sqlite3), Google APIs (googleapis), WebSockets (ws), React, Vite, Tailwind, Zustand, Zod.

**Spec:** `docs/superpowers/specs/2026-09-26-baba-tts-design.md`

## Global Constraints

- Do not use Bun-specific APIs. Use normal Node.js + npm tooling.
- Keep Google client secrets and refresh tokens on the backend only.
- Development HTTP port must be 7060.
- All persistent data goes into SQLite. No Redis, Mongo, etc.
- UI must be dark-themed, accessible, and suitable for an OBS Browser Dock.
- Treat untrusted user chat input securely.

## Review Focus

- Invalid or expired OAuth tokens: If the refresh token is revoked, the app should gracefully redirect or prompt the user to re-authenticate instead of crashing.
- YouTube API Rate Limits / Transient Errors: The polling loop must catch HTTP 500s or 429s from YouTube and back off instead of crashing the backend.
- High-volume chat memory leaks: Zustand store must bounded (e.g., max 500 items) so OBS doesn't lag after 3 hours.
- Unauthorized moderation requests: `POST /api/moderate` must strictly verify the local session cookie to prevent CSRF or external tampering.

### Task 2: SQLite & Google OAuth

**Files:**
- Create: `src/backend/db.ts`
- Create: `src/backend/auth.ts`
- Create: `src/backend/server.ts`

**Interfaces:**
- Consumes: `client_secret_*.json` in project root.
- Produces: Configured Hono server on port 7060 with `/auth/google` and `/auth/google/callback` routes. A valid session cookie and DB record.

- [ ] **Step 1: Setup SQLite Schema**
In `src/backend/db.ts`, initialize `better-sqlite3`. Create tables: `oauth_accounts (id, refresh_token, channel_id)` and `sessions (id, account_id)`.

- [ ] **Step 2: Implement Google OAuth Routes**
In `src/backend/auth.ts`, use `googleapis` to read the local `client_secret_*.json`. 
Export a Hono router with `GET /auth/google` (generates auth URL with `youtube.readonly` and `youtube.force-ssl` scopes, `access_type: 'offline'`).
Export `GET /auth/google/callback` to exchange code for tokens, save `refresh_token` to DB, and set an HttpOnly secure cookie for the local session.

- [ ] **Step 3: Wire up Hono Server**
In `src/backend/server.ts`, mount the auth router. Start `@hono/node-server` on port 7060.

- [ ] **Step 4: Test server starts**
Run `npx tsx src/backend/server.ts`. Verify it boots on 7060.

### Task 3: YouTube Chat Polling & WebSockets

**Files:**
- Create: `src/backend/youtube.ts`
- Create: `src/backend/ws.ts`
- Modify: `src/backend/server.ts`

**Interfaces:**
- Consumes: `db.ts` (for refresh token), `shared/types.ts` (for message format).
- Produces: WebSocket server broadcasting `ChatMessage` arrays to connected clients.

- [ ] **Step 1: Create WebSocket Broadcaster**
In `src/backend/ws.ts`, attach a `ws` Server to the Hono Node server instance. Export a function `broadcastMessage(msg)`.

- [ ] **Step 2: Implement YouTube Polling Loop**
In `src/backend/youtube.ts`, export `startYouTubePoller(accountId)`. 
1. Use `googleapis` with the DB refresh token to fetch `liveBroadcasts.list` (active).
2. Extract `liveChatId`.
3. Loop `liveChatMessages.list` based on `pollingIntervalMillis`.
4. Map incoming messages to `ChatMessage` type and call `broadcastMessage(msg)`.

- [ ] **Step 3: Handle API Errors**
Wrap the polling fetch in a try/catch. On HTTP 429/500, wait 10 seconds before retrying to prevent crash loops.

- [ ] **Step 4: Mount to Server**
In `src/backend/server.ts`, upon successful OAuth callback (Task 2), trigger `startYouTubePoller`. Attach WS to the server instance.

- [ ] **Step 5: Commit**
```bash
git add src/backend/
git commit -m "feat: youtube polling and websocket broadcasting"
```

### Task 5: Moderation Endpoints & UI

**Files:**
- Create: `src/backend/moderation.ts`
- Modify: `src/backend/server.ts`
- Modify: `frontend/src/components/ChatMessage.tsx`

**Interfaces:**
- Produces: `POST /api/moderate` endpoint.

- [ ] **Step 1: Backend Moderation API**
In `src/backend/moderation.ts`, export a Hono router.
Add `POST /api/moderate`. Parse Zod body (`messageId`, `action`). Verify session cookie. 
If action == 'delete', call `youtube.liveChatMessages.delete`. 
If timeout/ban, call `youtube.liveChatBans.insert`.
Broadcast a WS event to delete the message from the UI.

- [ ] **Step 2: Mount Moderation Router**
In `src/backend/server.ts`, mount the moderation router at `/api`.

- [ ] **Step 3: Frontend 3-Dot Menu**
In `frontend/src/components/ChatMessage.tsx`, add a hover-visible 3-dot button (using `lucide-react` icons). On click, show a small dropdown with "Delete", "Timeout (5m)", "Ban".

- [ ] **Step 4: Frontend API Call**
Wire the dropdown buttons to send `fetch('/api/moderate', { method: 'POST', body: ... })`. Let the WS handle removing the message locally once the backend broadcasts the deletion.

git commit -m "feat: full moderation loop"
